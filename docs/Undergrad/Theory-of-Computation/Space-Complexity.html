Space Complexity

Space Complexity

Jan 02, 202613 min read

Relevant to this is time complexity and more generally decidability

Space complexity shares many of the features of time complexity and serves as an additional dimension with which to classify problems

Definition: The space complexity of a deterministic Turing machine M that halts on all inputs is the function f:N→N, where f(n) is the maximum number of tape cells that M scans on any input of length n

We say M runs in space f(n)

If M is a nondeterministic Turing machine, we define its space complexity f(n) to be the maximum number of tape cells that M scans on any branch

Definition: We define space complexity classes SPACE(f(n)) as the set of languages decided by an O(f(n)) space deterministic Turing machine and NSPACE(f(n)) as the set of languages decided by an O(f(n)) space nondeterministic Turing machine

Space is more powerful than space because it can be reused

For example, we can reason that SAT can be reasonably solved in linear space, even though it’s an NP-complete problem

An important example we will look at is ALLNFA​={⟨A⟩∣A is an NFA and L(A)=Σ∗}

We can decide the complement ALLNFA​​ in linear space by nondeterministically reading in 2q inputs (this is the maximum before it will repeat) and updating the possible states of our NFA accordingly

Savitch’s Theorem: For any f(n)≥n, NSPACE(f(n))⊆SPACE(f2(n))

Our regular way of simulating an NTM is not sufficient, because it could potentially use 2O(f(n)) space

So how does one prove this? Let N decide A nondeterministically in space f(n)

We construct a deterministic TM M deciding A using the procedure CANYIELD, which tests whether a configuration of N can yield another within a specified number of steps

CANYIELD(c1​,c2​,t) works by recursively checking for each cm​ using space f(n) whether CANYIELD(c1​,cm​,2t​) and CANYIELD(cm​,c2​,2t​)

We modify N to clear the tape on accept and move the head to the leftmost cell, so that there is a single accept state, and select a constant d such that N has no more than 2df(n) configurations using f(n) tape

M= “On input w: Output the result of CANYIELD(cstart​,caccept​,2df(n))”

This is correct, but how much space does our CANYIELD method use? Well each level of the recursive stack must store c1​,c2​,t which takes O(f(n)) space, and there are O(log2df(n))=O(f(n)) levels, coming out to O(f2(n))

(A technical difficulty is that this requires M knowing the value of f(n), but we can actually determine this manually by simulating on each value until we know it has rejected, and this is fine from a space standpoint)

Definition: PSPACE is the class of languages decidable in polynomial space on a deterministic Turing machine, PSPACE=k⋃​SPACE(nk)

We can also define NPSPACE, but as we showed PSPACE=NPSPACE

So by Savitch’s theorem, since ALLNFA​ is in coNSPACE(n) we know it is also in PSPACE

We can easily reason P⊆PSPACE and NP⊆NPSPACE=PSPACE

Similarly, a TM that uses f(n) space cannot have more than f(n)2O(f(n)) configurations before repeats, so PSPACE⊆EXPTIME=⋃k​TIME(2nk)

In summary,
P⊆NP⊆PSPACE=NPSPACE⊆EXPTIME

Of these, the only certainty is P=EXPTIME, but general consensus is that these containments are all proper

PSPACE-Completeness

PSPACE has an analog to NP-Completeness

Definition: A language B is PSPACE-complete if B is in PSPACE and every A in PSPACE is polynomial time reducible to B

If B is not necessarily in PSPACE then we call it PSPACE-hard

The reason we use time reducibility instead of space reducibility is simply because time is much more limiting and a better representation of what we aim to achieve with completeness

To give an example, we introduce a more general type of Boolean formula which uses quantifiers in prenex normal form, known as quantified Boolean formulas (like ϕ=∀x∃y[(x∨y)∧(xˉ∨yˉ​)])

When each variable is within the scope of a quantifier, the formula is fully quantified, sometimes called a sentence

TQBF={⟨ϕ⟩∣ϕ is a true fully quantified Boolean formula}

Theorem: TQBF is PSPACE-complete

We can’t use the exact same method as with the Cook-Levin theorem, since the height of the tableau would be exponential and therefore cannot be produced in polynomial time

Instead, we use a technique related to our Savitch’s theorem proof

First, it’s apparent that we can specify a PSPACE algorithm that decides TQBF

Now let A be a language decided by a TM M in space nk for some constant k

For our reduction, we design a formula parameterized as ϕc1​,c2​,t​ where ϕ is true if M can go from c1​ to c2​ in at most t steps (for convenience a power of 2), and then our final reduction uses ϕcstart​,caccept​,h​ where h=2df(n) for a constant d

Like before, we define ϕc1​,c2​,t​ to encode that either c1​=c2​ or c2​ follows from c1​ in a single step of M, using the same ideas as in the Cook-Levin theorem

For t>1, we construct ϕc1​,c2​,t​ recursively

A naive approach might try ϕc1​,c2​,t​=∃m1​[ϕc1​,m1​,2t​​∧ϕm1​,c2​,2t​​], but this still gives an exponentially large formula

A working recursive definition that reduces the size is ϕc1​,c2​,t​=∃m1​∀(c3​,c4​)∈{(c1​,m1​),(m1​,c2​)}[ϕc3​,c4​,2t​​]

This is possible because we can define ∀(c3​,c4​)∈{…} in terms of Boolean operators, and so this definition properly adds O(f(n)) space for each division of t, yielding a formula of size O(f2(n))

PSPACE-Complete Problems

A game is loosely defined as a competition in which opposing parties attempt to achieve some goal according to prespecified rules

Games are closely related to quantifiers, which we will demonstrate with an artificial formula game

Let ϕ be some quantified Boolean formula in prenex normal form

Two players take turns selecting the values of the variables x1​,…,xk​; Player A selects values bound to ∀ quantifiers and Player E selects values bound to ∃ quantifiers

Player A wins if ψ, the part of the formula without the quantifiers, is false, and Player E wins if it is true

We say that a player has a winning strategy for a game if that player can always win the game

FORMULA-GAME={⟨ϕ⟩∣ Player E has a winning strategy in the formula game associated with ϕ}

Theorem: FORMULA-GAME is PSPACE-complete

This is clearly true because Player E wins precisely if ϕ∈TQBF, that is the process of choosing variables in order is exactly the condition under which a quantified variable is true or not

Let’s look at another kind of game based on geography, the children’s game in which players take turns naming cities that begin with the last letter of the previous city, until there are no option available

In generalized geography, we take an arbitrary directed graph with a designated start node

GG={⟨G,b⟩∣ Player I has a winning strategy for the generalized geography game played on graph G starting at node b}

Theorem: GG is PSPACE-complete

First, we can solve GG with a recursive brute-force algorithm, which only requires the space of the recursion stack, i.e. linear space

To map the formula game to GG, we use a diamond construction somewhat reminiscent of the proof of HAMPATH’s NP-completeness, but much simpler

We first map ϕ to a formula whose quantifiers start and end with ∃ and strictly alternate between ∃ and ∀, which we can easily do with dummy variables

Then, the geography game that simulates ϕ goes in two parts

  1. Players alternate selecting edges that represent the values of x1​,…,xk​
  2. Player A chooses a clause, and then Player E wins if they can choose a satisfied variable

In other words, no polynomial time algorithm exists for optimal play in generalized geography unless P=PSPACE, which is even stronger than P=NP

It would be nice if our methods could be applied to games like chess, however conventional board games have a finite state space and are thus unsuitable for asymptotic analysis

The Classes L and NL

If we modify our computational model slightly, we can meaningfully consider sublinear space bounds

We consider a two-tape model, where one tape is limited to the size of the input and is read only

With this model, we can exclude the size of the input from our space analyses

Definition: L=SPACE(logn) is the class of languages that are decidable in logarithmic space on a deterministic Turing machine

Definition: NL=NSPACE(logn) is the class of languages that are decidable in logarithmic space on a nondeterministic Turing machine

We consider logarithmic space because it is much smaller than linear but still solves useful problems, and happens to be robust under machine model and input encoding changes

One way of understanding the power of logarithmic space is with indices/pointers, which are logarithmic on the input size

Example: A={0k1k∣k≥0}
We can’t use our zig-zag approach, crossing off 0s and 1s, since that requires O(n) space

Instead, we run through the input and use two binary counters to keep track of the number of 0s and 1s, and compare the counters at the end

In binary, each counter uses only logarithmic space, so this algorithm runs in O(logn) space, and A∈L

This is a very intuitive algorithm, but using counters is quite difficult to demonstrate explicitly in the Turing machine model

Example: PATH
We can solve this in O(logn) by only keeping track of the current node, and nondeterministically moving to the next one, until we either find the target or use m steps

So PATH is in NL

Our earlier claim that f(n) space bounded Turing machines also run in time 2O(f(n)) is no longer true for very small space bounds, because our definitions have changed

We can analyze sublinear spaces with an updated definition of machine configurations

Definition: If M is a Turing machine that has a separate read-only input tape and w is an input, a configuration of M on w is a setting of the state, the work tape, and the positions of the two tape heads, but not the input w

If M runs in f(n) space and w is an input of length n, the number of configurations of M on w is n2O(f(n)), since each configuration stores the working tape and the location of the pointer on the read-only tape

So our bound accounting for sublinear spaces is n2O(f(n))

Similarly, we can slightly modify the proof of Savitch’s Theorem to account for the updated definition, and the result is the same

NL-Completeness

Surprise! NL also has an analogue to NP-Completeness

Everything is about the same, however since all NL problems are solvable in polynomial time, we use a new kind of reducibility

Definition: A log space transducer is a Turing machine with a read-only input tape, a write-only output tape, and a read/write work tape, where the output tape cannot move leftward, and the work tape may contain O(logn) symbols

A log space transducer M computes a log space computable function f:Σ∗→Σ∗ where f(w) is the string remaining on the output tape after M halts when it is started with w on its input tape

Language A is log space reducible to language B, written A≤L​B, if A is mapping reducible to B by means of a log space computable function f

Definition: A language B is NL-complete if B∈NL and every A in NL is log space reducible to B

Theorem: If A≤L​B and B∈L, then A∈L

A naive approach would be directly mapping w to f(w), however f(w) could be too large for the log-space bound

Instead, we trade time for space and recompute from scratch individual symbols whenever requested, such that only a single symbol of f(w) needs to be stored at any point

Corollary: If any NL-complete language is in L, then L=NL

Theorem: PATH is NL-complete

We map a log space Turing machine M to a graph G, where the nodes represent configurations of M on w, with an edge from c1​ to c2​ if c2​ is a possible next configuration of M starting from c1​

We modify M to have a unique accepting configuration, designated as t

This machine can operate in log space by sequentially going through all possible strings of length clogn and outputting them if valid configurations, and likewise for edges

Corollary: NL⊆P

This follows simply from the fact that a Turing machine using f(n) space runs in n2O(f(n)), so log space reducers run in polynomial time, and therefore every language in NL is polynomial time reducible to PATH, which is in P

Log space reducibility is actually adequate for most reductions, and it terms out is enough for reductions like the PSPACE reduction to TQBF, which can be useful in understanding relationships like NL⊊PSPACE

NL Equals coNL

NP and coNP are generally believed to be different, and our intuition would expect this fact to carry over to NL

Theorem: NL=coNL

The essence of the proof is showing that PATH is in NL, and therefore the rest of coNL

While this algorithm is not tricky to verify, I personally found the nondeterministic reasoning used to construct it tricky to fully grasp

We first calculate c, the number of nodes reachable from s
This cannot be done directly in logarithmic space, however we can use an iterative method

We calculate ci+1​ from ci​ by going through all nodes v of G and checking if any node reachable in i steps has an edge to v

How do we make sure we’ve checked every node reachable in i steps? Nondeterminism doesn’t help us for this, and we can’t just store the nodes reachable in i because of the space constraint

We solve this by nondeterministically selecting a path to every node in u, and incrementing an auxiliary variable d
If we find v then great, but otherwise we check if d=ci​ and reject otherwise

Now that we have our value c, we can nondeterministically select paths to each node (excluding t) and accept only if we reach c nodes

Since we exclude t from this search, reaching c nodes means t is not reachable, which concludes the algorithm

Since we only use counter variables, this algorithm runs in logarithmic space, and therefore NL=coNL

Our present knowledge of the relationships among complexity classes is L⊆NL=coNL⊆P⊆NP⊊PSPACE

The strict subset of NP in PSPACE is shown here

Most researchers conjecture that all these containments are proper, but we do not have the tools to prove much about it
